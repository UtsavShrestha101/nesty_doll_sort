# What `nesty-test` covers

`tools/scripts/nesty-test` is the one command that checks the whole game (README "Tests and analysis"). This file lists each feature with what checks it:

- **Host:** the tests `nesty-test`'s host checks run.
- **Device:** the on-device step, with its screenshots.
- **Not on a device:** what the device run can't drive yet, and why.

CLAUDE.md "Testing" makes this a rule (D169). Every new or changed feature gets its host tests, a device step in `nesty-test`, and its row here, in the same change. `tools/test/test_coverage_test.dart` fails if a game feature folder or an `integration_test/*_test.dart` file has no row here, or if an integration test isn't run by `nesty-test`.

## The two parts of a run

- **Host checks** (skip them with `--device-only`). These are CI's checks, except codegen drift:
  - `dart format`, `flutter analyze --fatal-infos --fatal-warnings`;
  - every test suite: nesty_core, nesty_render, the game (cubit, widget, page, overflow at 5 sizes × 2 text scales, ethics, contracts), the admin, and tools;
  - nesty_core's web parity on node, chrome and dart2wasm (each skipped when the tool is missing);
  - the design, asset, FX, font-subset and TODO-index drift checks;
  - the overflow suite again in every other locale (de, es, fr, hi, id, ja, pt, pt_BR, tr: `--dart-define=NESTY_TEST_LOCALE`);
  - the level bundle and the solver fixtures;
  - the admin's web build.

  So every feature's host tests run on every `nesty-test`.
- **Device checks.** The dev flavor with every real service, from a fresh install, on the iPhone 16 Pro simulator (or any simulator by name or UDID: `--device`, `NESTY_TEST_IOS_DEVICE`) or the API 35 emulator (`--android-size WxH@dpi` resizes it for one run). Each has an `--only` name:
  - every check but `locales_test` and `daily_fingerprint_test` pins the phone's language to English first (`support/phone_language.dart`, `pinEnglishPhone`), so a simulator left in another language can't fail them;
  - `playthrough`: `playthrough_test.dart`, with its screenshots;
  - `resume`: `resume_phase_a_test.dart` and `resume_phase_b_test.dart`, kill mid-level, then resume, twice: `NESTY_RESUME_SCENARIO` `l3` (M3) and `l1` (E9, a kill during level 1's tutorial);
  - `daily`: `daily_fingerprint_test.dart`, the daily's board against nesty_core's;
  - `board`: `board_layouts_test.dart`, levels 31–200's layouts (M7 phase 4);
  - `race`: `race_loss_test.dart` three times, scenarios `loss` (`NESTY_RACE_PACE_MS=250`), `oom` (`NESTY_RACE_PACE_MS=600000`) and `restart` (`NESTY_RACE_PACE_MS=1000`);
  - `meta`: `meta_screens_test.dart` three times (`NESTY_META_SCENARIO`): `returning` (Home, Chapters, the Museum, Records and the Shop on a seeded returning player), `finale` and `complete`;
  - `daily_states`: `daily_states_test.dart` four times with `NESTY_FAKE_DATE`, scenarios `chest`, `paused`, `saved` and `settings`;
  - `gift`: `login_gift_test.dart` five times with `NESTY_FAKE_DATE` and `NESTY_GIFT_SCENARIO`, scenarios `ready`, `claimed`, `day7`, `clock_back` and `hint` (shots `g_`);
  - `overlays`: `overlays_test.dart`, the gameplay overlays on a seeded save;
  - `faults`: `faults_test.dart` eight times (`NESTY_FAULT_SCENARIO`), the failure states and the splash held once its art is in (10.8) through the test-only seam `bootstrap(beforeRunApp:)` (M7 phase 5);
  - `semantics`: `semantics_tour_test.dart` four times (`NESTY_A11Y_SCENARIO`): what a screen reader gets on each screen (M7 phase 5);
  - `reminder`: `reminder_test.dart`, Android only, run with `--only reminder`.
  - `locales`: `locales_test.dart` three times (`NESTY_TEST_LOCALE`), one per script family (5B, l10n.md 7.2): German through the real language picker, Hindi and Japanese seeded. Each walks Home to a race's Leave race, with every assertion read from the locale's own catalog and each screen shot as `l10n-<code>-NN_<screen>`.

  Each phase 4 and 5 file seeds its own save (`integration_test/support/seeded_save.dart`) and prefixes its screenshots: `b_`, `r_`, `meta-`, `d_`, `g_`, `ov_`, `f_`, `s_`. The playthrough's have no prefix. All of them land in `<run>/screenshots/`.
