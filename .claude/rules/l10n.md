# Localization rules

- Each app owns its catalog: `apps/<app>/lib/l10n/app_en.arb` is the source of
  truth, configured by `apps/<app>/l10n.yaml` (`nullable-getter: false`, so no
  `!` at call sites).
- **English only today.** Spec §16 plans es, pt-BR, id, hi, de, fr, tr and ja
  after launch. When a locale is added, it gets **every** key with a **real**
  translation. Never use `TODO_TRANSLATE:` or any other placeholder text, and
  never copy the English value as a stand-in.
- Every user-facing string goes through ARB, including error fallbacks,
  tooltips, semantics labels and admin-panel copy. Access it with
  `context.localizations.someKey` (`core/extensions/context_extension.dart`).
- Keys are camelCase and describe the meaning, not the widget: `levelTitle`,
  `outOfMovesTitle`.
- Every key has an `@key` block with a `description` (where it appears, citing
  the spec section) and typed `placeholders`:
  ```json
  "levelTitle": "Level {level}",
  "@levelTitle": {
    "description": "Home play button and gameplay top bar (spec §10.2 #2, #3).",
    "placeholders": { "level": { "type": "int", "example": "24" } }
  }
  ```
- Use ICU `plural`/`select` for counts ("{count, plural, one{…} other{…}}").
  Never concatenate strings or add an "s".
- Keep strings short (spec §16), because German and French run long in
  chunky buttons. Menus must still fit at 1.3× text scale.
- Don't localize internal identifiers: doll color ids (`red`), level ids,
  analytics event names, Remote Config keys and product IDs are data. Show the
  player-facing names (for example "Cherry") through ARB keys.
- Map `AppExceptionKind` to ARB text only through
  `AppExceptionL10n.localizedMessage(l10n)` in
  `lib/core/extensions/app_exception_extension.dart` (both apps; an exhaustive
  switch, so a new kind forces a decision). Never switch on kinds in a widget,
  and never render `exception.message`.
- Generated files `lib/l10n/app_localizations*.dart` are never edited (the
  block-generated hook refuses). After an `.arb` change, run
  `cd apps/<app> && flutter gen-l10n`.
- Use the `/l10n` skill or the `l10n-specialist` agent for anything touching
  more than one key.
